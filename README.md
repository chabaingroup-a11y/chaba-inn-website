# Chaba Inn — เว็บไซต์จองตรง (chabainn.com)

เว็บไซต์จองตรงของ Chaba Group ฉบับใช้งานได้จริง (ไม่ใช่มอกอัพ) เขียนด้วย Next.js 14 + Prisma
ประกอบด้วยส่วนหน้าบ้าน (ลูกค้าเห็น) และระบบหลังบ้าน (ผู้ดูแลจัดการ) ที่เชื่อมกับฐานข้อมูลจริงตัวเดียวกัน
แก้ไขอะไรในหลังบ้านจะเห็นผลที่หน้าบ้านทันที

**ขอบเขตของโค้ดชุดนี้:** ปุ่ม "กดจอง" ของทุกห้องพักลิงก์ไปที่ LINE OA ของสาขานั้นให้ลูกค้าทักไปคุย/ยืนยันกับพนักงานเอง
ตามที่ตกลงกันไว้ ไม่ได้ทำระบบชำระเงินออนไลน์หรือระบบจัดการสถานะการจอง (รอยืนยัน/ยืนยันแล้ว/เช็คอิน ฯลฯ)
ในโค้ดชุดนี้ — ถ้าภายหลังต้องการเพิ่มส่วนนั้น (ตามที่เคยระบุไว้ในเอกสารออกแบบระบบฉบับแรก) แจ้งได้
เดี๋ยวเพิ่มให้เป็นโมดูลต่อยอด

## ⚠️ สิ่งที่ต้องรู้ก่อนเริ่ม — ยังไม่ได้ทดสอบรันจริงในเครื่องนี้

เครื่องมือที่ใช้เขียนโค้ดชุดนี้ไม่มีสิทธิ์เข้าถึง npm registry (ถูกบล็อกโดยนโยบายเครือข่ายขององค์กร)
จึงไม่สามารถรัน `npm install` เพื่อทดสอบว่าโค้ดคอมไพล์ผ่านจริงได้ในสภาพแวดล้อมนี้
โค้ดถูกเขียนและตรวจทานอย่างละเอียดด้วยมือตามหลักการของ Next.js 14 / Prisma 5 ที่ถูกต้อง
แต่ **แนะนำให้รัน `npm install` แล้วลอง `npm run dev` ในเครื่องของคุณหรือของทีมพัฒนาก่อนใช้งานจริง**
เผื่อพบจุดที่ต้องปรับเล็กน้อยตามเวอร์ชันแพ็กเกจ ณ เวลาที่ติดตั้งจริง

## เริ่มต้นใช้งาน (Local Development)

ต้องมี Node.js เวอร์ชัน 18 หรือ 20 (LTS) ขึ้นไป

```bash
# 1. ติดตั้งไลบรารี
npm install

# 2. ตั้งค่าตัวแปรแวดล้อม
cp .env.example .env
# แล้วเปิดไฟล์ .env แก้ SESSION_SECRET ให้เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร
# (สร้างได้ด้วยคำสั่ง: openssl rand -base64 32)
# และตั้งชื่อผู้ใช้/รหัสผ่านผู้ดูแลหลักที่ต้องการใน SEED_ADMIN_USERNAME / SEED_ADMIN_PASSWORD

# 3. สร้างฐานข้อมูล SQLite และตารางทั้งหมด
npm run db:push

# 4. ใส่ข้อมูลตั้งต้น (5 สาขา, ห้องพัก, โปรโมชัน, บัญชีผู้ดูแลหลัก)
npm run db:seed

# 5. รันเซิร์ฟเวอร์พัฒนา
npm run dev
```

เปิดเบราว์เซอร์ไปที่:
- **http://localhost:3000** — หน้าบ้านสำหรับลูกค้า
- **http://localhost:3000/admin/login** — หลังบ้าน (login ด้วยค่าที่ตั้งไว้ใน `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD`)

**เปลี่ยนรหัสผ่านผู้ดูแลหลักทันทีหลังเข้าใช้งานจริงครั้งแรก** (ตอนนี้ยังไม่มีหน้าเปลี่ยนรหัสผ่านในตัว
ต้องรัน script เพิ่มหรือแก้ผ่าน Prisma Studio: `npx prisma studio`)

## โครงสร้างระบบ

- **ฐานข้อมูล:** SQLite ไฟล์เดียว (`dev.db`) ผ่าน Prisma ORM — โครงสร้างตารางอยู่ที่ `prisma/schema.prisma`
  มี 5 ตารางหลัก: `Branch` (สาขา), `Room` (ประเภทห้อง+ราคา), `Photo` (รูปภาพห้อง), `Promotion` (โปรโมชัน), `User`/`StaffBranch` (บัญชีผู้ดูแลและสิทธิ์การเข้าถึงรายสาขา)
- **หน้าบ้าน:** `src/app/page.tsx` (รายการสาขา) และ `src/app/branch/[slug]/page.tsx` (รายละเอียดห้องพัก + ปุ่มกดจอง)
  อ่านข้อมูลจากฐานข้อมูลโดยตรงทุกครั้งที่โหลดหน้า (ไม่มีแคชค้าง)
- **หลังบ้าน:** `src/app/admin/` — ป้องกันด้วย session (iron-session) ตรวจสอบสิทธิ์ทุก request ทั้งฝั่งหน้าเว็บและ API
  - `/admin/rooms` — เพิ่ม/ลบ/เปิด-ปิดขายห้อง ตั้งราคาและประเภทเตียง
  - `/admin/promotions` — เพิ่ม/ลบโปรโมชันและเปอร์เซ็นต์ส่วนลด
  - `/admin/photos` — อัปโหลด/ลบรูปภาพจริงต่อห้อง (เก็บไฟล์ที่ `public/uploads/`)
  - `/admin/policy` — นโยบายสัตว์เลี้ยงหลักถูกล็อกไว้ในโค้ด (ไม่มีค่าใช้จ่าย/ไม่จำกัดน้ำหนัก/จำนวน/พื้นที่ + ห้ามทิ้งไว้ลำพัง) แก้ได้แค่กฎเพิ่มเติมรายสาขา
  - `/admin/settings` — ตั้งค่าลิงก์ LINE OA, เบอร์โทร, Facebook ต่อสาขา
- **สิทธิ์ผู้ใช้งาน:** `User.role` เป็น `"ADMIN"` (ผู้ดูแลหลัก แก้ได้ทุกสาขา) หรือ `"STAFF"` (ผู้ช่วย แก้ได้เฉพาะสาขาที่ผูกไว้ในตาราง `StaffBranch`)
  เพิ่มผู้ใช้ใหม่ได้ผ่าน `npx prisma studio` ไปก่อน (ยังไม่มีหน้าเพิ่มผู้ใช้ในตัว)

## ข้อจำกัดสำคัญที่ต้องรู้ก่อนขึ้นใช้งานจริง

1. **รูปภาพ:** เก็บไฟล์ไว้ที่ `public/uploads/` บนดิสก์ของเซิร์ฟเวอร์ วิธีนี้ใช้ได้กับโฮสติ้งที่มีดิสก์ถาวร
   (VPS, Docker container ที่ไม่ restart บ่อย) **แต่ใช้ไม่ได้กับแพลตฟอร์ม serverless อย่าง Vercel**
   เพราะไฟล์ระบบเป็นแบบชั่วคราว รูปจะหายเมื่อรีดีพลอย — ถ้าจะขึ้น Vercel ต้องเปลี่ยนไปเก็บที่ Amazon S3,
   Cloudflare R2 หรือ Cloudinary แทน (แก้เฉพาะ `src/app/api/photos/route.ts` และ `[id]/route.ts`)

2. **ฐานข้อมูล SQLite:** เหมาะสำหรับเริ่มต้นและปริมาณการใช้งานของโรงแรมขนาดนี้ แต่ถ้าเซิร์ฟเวอร์รันหลาย instance
   พร้อมกัน (เช่น auto-scale) ต้องย้ายไป PostgreSQL — แก้แค่ `provider = "postgresql"` ใน `prisma/schema.prisma`
   และตั้ง `DATABASE_URL` เป็น connection string ของ Postgres แล้วรัน `npm run db:push` ใหม่

3. **แผนที่และรีวิว (Google Maps / Google Reviews):** ยังไม่ได้เชื่อมต่อจริงในโค้ดชุดนี้ ทำได้ภายหลังตามนี้:
   - **แผนที่:** สมัคร Google Cloud Console ผูกบัตร/บัญชีเรียกเก็บเงิน (มีเครดิตฟรีรายเดือน) แล้วฝัง
     Google Maps Embed API หรือ Maps JavaScript API ที่หน้า `src/app/branch/[slug]/page.tsx`
     โดยใช้พิกัด `lat`/`lng` ที่เตรียมฟิลด์ไว้ให้แล้วในตาราง `Branch`
   - **รีวิว:** ดึงผ่าน Google Places API ได้ แต่แสดงได้สูงสุด **5 รีวิวต่อสาขา** และต้องมีเครดิต/โลโก้ Google กำกับเสมอ
     ตามนโยบายของ Google ห้ามตัดต่อเนื้อหารีวิว — ถ้าต้องการมากกว่านั้นให้ใช้บริการ widget เจ้าอื่น เช่น
     Elfsight, Trustindex, EmbedSocial (มีค่าบริการรายเดือน)

4. **ยังไม่มีระบบชำระเงินออนไลน์และระบบสถานะการจอง** — เป็นไปตามที่ตกลงกัน (จองผ่าน LINE OA แทน)

5. **ยังไม่มีหน้าเปลี่ยนรหัสผ่านหรือหน้าเพิ่มผู้ใช้งาน** ใน UI — จัดการชั่วคราวผ่าน `npx prisma studio`
   หรือแจ้งได้ถ้าต้องการให้เพิ่มหน้าเหล่านี้

## การขึ้นใช้งานจริงบน chabainn.com

1. เลือกโฮสติ้งที่รองรับ Node.js และมีดิสก์ถาวร (เช่น VPS ธรรมดา, Railway, Render, DigitalOcean App Platform)
   — หลีกเลี่ยง Vercel ถ้ายังใช้การเก็บรูปแบบ local ตามข้อจำกัดข้อ 1 ด้านบน
2. ตั้งค่า environment variables บนโฮสติ้งจริง (`DATABASE_URL`, `SESSION_SECRET` ที่สุ่มใหม่และเก็บเป็นความลับ)
3. รัน `npm install && npm run build && npm run db:push && npm run db:seed && npm run start`
4. ชี้ DNS ของโดเมน chabainn.com มาที่โฮสติ้งนี้ (A record หรือ CNAME ตามที่โฮสติ้งกำหนด)
5. เปลี่ยนรหัสผ่านผู้ดูแลหลักทันที และลบ/เปลี่ยนบัญชีตัวอย่างถ้าจำเป็น
